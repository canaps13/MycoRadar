# MR-015 — Noms candidats et associations écologiques sourcées

## Périmètre

Quatre noms candidats, cinq associations bibliographiques et un lecteur hors HTTP
contrôlant les réponses taxonomiques conservées. Branche indépendante de `main`
`36e4ee8`, sans fusion des PR précédentes. Dockerfile, lockfiles, serveur HTTP et
catalogue public restent identiques. `/v1/species` et la carte ne sont pas alimentés
par ce catalogue interne ; aucun pilote ni occurrence n'est admis.

**MR-015 reste `IN_PROGRESS`.** Les paramètres quantitatifs, la correspondance des
concepts d'espèces des études avec les données actuelles et le transfert terrain
restent à établir. MR-045/MR-046 et les sources admises demeurent nécessaires avant
MR-016/MR-017. Cette tranche ne calcule ni features ni scores.

## Contrat et paramètres

`species-ecology-v1` contient référence, bibliographie et candidats avec réponses
sources, associations, concept, admission et paramètres. Le lecteur ne télécharge
rien et ne dépend pas du code des PR en attente. Les paramètres d'habitat sont
`soil_ph`/`pH` et `elevation_m`/`m` : bornes finies optionnelles et sources, toujours
`scoring_enabled:false`. Toutes les bornes du catalogue réel sont `null`. Une
hypothèse numérique exige référence et bornes cohérentes, mais reste désactivée :
une citation ne démontre pas la validité du nombre ou son transfert. Aucun poids,
fenêtre météo, calendrier de fructification ou mélange des deux scores.

Limites : `concept_alignment:not_verified`, `transfer_to_pilot:unvalidated`,
`exhaustive_host_list:false`, `pilot_admission:not_admitted`. Toutes les sources
bibliographiques sont `training_use:not_admitted`. Reçu `partial`, deux scores et
résolution effective `null`, `publication_allowed:false`.

Bornes : manifeste 512 Kio, 100 candidats et 100 références, 30 associations et dix
paramètres par candidat. Chaque réponse est limitée à 128 Kio, chemin relatif
résolu dans le répertoire du manifeste, fichier ordinaire et SHA vérifié ; jusqu'à
200 lectures séquentielles. URL GBIF HTTPS confrontées au nom et à la clé, sans
appel réseau. Clés JSON répétées, références inconnues, doublons, unités ou dates
incohérentes, non-finis de paramètres, corruption et erreurs tardives annulent le
reçu entier. Dates ISO avec fuseau, sans conversion implicite Unix. Diagnostic CLI
fixe sans chemin, argument ou corps fournisseur.

Un SHA vérifie l'identité avec la capture déclarée, sans signature d'origine.
Le programme ne vérifie pas le contenu des articles cités. Curation et revue de
droits demeurent requises, notamment pour les textes de licence inconnue. Les
[preuves sources et droits](evidence/MR-015-sources.json) distinguent lectures,
index et refus ; aucun PDF ou corps d'article n'est dans le dépôt.

## Exécution et validation

```powershell
$env:PYTHONPATH='api/src'
uv run --locked python -m mycoradar.species_ecology --manifest data/species/catalog.json
uv run --locked python scripts/check_species_catalog.py --manifest data/species/catalog.json
docker build -t mycoradar-api:local -f infra/api.Dockerfile .
$mr015Input = (Resolve-Path data/species).Path
$mr015Smoke = (Resolve-Path scripts/check_species_catalog.py).Path
docker run --rm --network none --mount "type=bind,source=$mr015Input,target=/input,readonly" --mount "type=bind,source=$mr015Smoke,target=/smoke.py,readonly" mycoradar-api:local python /smoke.py --manifest /input/catalog.json
```

La CLI utilise les dépendances de production existantes. La CI exécute le vrai
catalogue capturé dans l'image API, hors réseau et entrées en lecture seule,
vérifie deux stdout identiques et conserve l'API non root sans modules
géographiques. Les URL fictives des tests ne sont jamais contactées.
Réussis localement : 396 tests Python dont 53 nouveaux, Ruff lint/format,
mypy (21 sources), `git diff --check` et build de l'image API. Les 51 intégrations
PostGIS sont ignorées localement faute de base de test activée ; les suites
PostGIS et frontend sont confiées à la CI de cette branche, encore en attente.

Le smoke réel passe sous Windows et Docker : quatre noms, cinq associations,
zéro seuil configuré, zéro admission et sorties CLI identiques au rejeu. Les reçus
natifs et Docker sont égaux. Conteneur UID 10001, réseau désactivé et entrées en
lecture seule ; contrat santé présent et Shapely/pyproj absents. Le diff confirme
que le serveur HTTP et le catalogue public sont inchangés. Voir la
[preuve locale](evidence/MR-015-sample.json).

Les tests couvrent intégrité et chemins, absence de réseau, refus des synonymes,
matches flous, rangs/royaumes/jeux incohérents, unités, dates, références et erreurs
tardives sans reçu partiel. Une hypothèse numérique inventée en test reste sans
effet sur les scores. Le premier mypy a relevé une union inférée trop générale
des types de faits ; les références sont maintenant contrôlées séparément et
mypy réussit. Une première application documentaire au mauvais contexte a été
refusée sans changement, puis corrigée. Les URL bibliographiques refusées ou
vides sont distinguées des textes réellement utilisés dans la preuve sources.

Retour arrière : retirer lecteur, catalogue interne, smoke et documentation puis
reconstruire l'API. Aucune migration, occurrence importée, localisation diffusée,
admission scientifique, secret, déploiement ou dépense cloud.
