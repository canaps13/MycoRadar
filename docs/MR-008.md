# MR-008 — Carte des territoires pilotes

La carte MapLibre GL JS représente les contours administratifs réels des
Bouches-du-Rhône, du Var et du Vaucluse. La Provence reste une configuration
pilote : les identifiants, noms, géométries, emprises et points des étiquettes
proviennent du catalogue généré, pas d'une règle métier dans le composant carte.
Cette livraison ne dépend ni des tables PostGIS de MR-006 ni du job de grille de
MR-007, encore proposés dans des PR séparées. Elle réutilise exactement le fichier
source IGN de MR-007, sans embarquer son implémentation ou sa migration.

## Fonctionnement et limites

- Zoom, déplacement, retour à la vue d'ensemble et sélection par polygone.
  Les mêmes secteurs sont sélectionnables au clavier dans la liste.
- Légende et crédits IGN / Licence Ouverte 2.0 / Natural Earth / MapLibre visibles
  sur les deux formats. Les licences du moteur sont livrées avec le frontend.
- Fond terre/mer généralisé, sans routes ni indication de propriété, d'accès ou
  de forêt. Échelle Natural Earth 1:10 millions : **aucune précision de 10 m**.
  Le décalage possible des côtes entre les deux sources ne constitue pas un
  masque terre/mer scientifique.
- Habitat et fructification indiqués séparément comme indisponibles, avant et
  après sélection. Aucun score, occurrence, espèce, prévision ou résultat fictif.
  Le service de santé HTTP ne détermine pas la disponibilité scientifique.
- Chargement, source cartographique inaccessible et absence de WebGL couverts.
  L'échec conserve les boutons de sélection, les crédits et les états de données ;
  un bouton permet de réessayer la carte.
- Aucun appel client à un fournisseur de tuiles, police, sprite ou géolocalisation.
  Toutes les ressources du moteur et les géométries sont servies par l'origine
  MycoRadar ; le test navigateur contrôle l'absence de requêtes HTTP externes.
  Les liens de sources restent consultables volontairement.

La sélection est un état local React, sans stockage, transmission ou observation
personnelle. Les calculs scientifiques restent à implémenter dans les services
backend. Les simplifications, découpes et points d'étiquettes sont calculés par
le script **hors requête**, jamais dans l'interface.

## Sources et traçabilité

Le [manifeste](../data/map-sources/manifest.json) contient URL de collecte,
licence, attribution, version et SHA-256 des entrées. Le
[reçu](../data/map-sources/output-receipt.json) lie le script, ses dépendances,
le manifeste, les sorties et leurs empreintes. Les GeoJSON publics portent une
empreinte dans leur URL ; les chemins sont compilés dans le catalogue frontend.
Le [reçu frontend autonome](../web/map-bundle-receipt.json) contrôle les mêmes
ressources et la recette dans un contexte ne contenant que `web`, comme Docker.
Le contrôle complet des sources est exécuté par `npm test`, séparément du build.
Les dates affichées sont les dates de collecte, jamais une fraîcheur estimée.
Publication et résolution effective restent explicitement inconnues.

| Lot | Origine et transformation | Droits et dates |
|---|---|---|
| IGN ADMIN EXPRESS COG CARTO, départements 13/83/84 | WFS public LATEST, CRS:84 longitude/latitude ; original conservé dans `data/territories/provence/ign-adminexpress-source.geojson` ; simplification d'affichage à 0,0005° | Licence Ouverte 2.0 ; extrait collecté le 29 octobre 2026 à 17:06:20 UTC ; édition inconnue, lien effectif vers la source affiché |
| Natural Earth Land 1:10 millions | GeoJSON du dépôt producteur au commit `ca96624a56bd078437bca8184e78163e5039ad19` ; découpe longitude −12 à 20, latitude 33 à 53 ; simplification d'affichage à 0,002° | Domaine public ; collecte le 29 octobre 2026 à 23:03:28 UTC ; publication/actualisation du contenu non établies |

Les tolérances sont des paramètres angulaires de présentation, sans revendication
de résolution métrique. La navigation est bornée à l'emprise du fond local.
Les conditions des lots et les décisions de réutilisation sont consignées dans
le [registre des fournisseurs](data-providers.md#lots-cartographiques-admis-par-mr-008).

## Reproduire les ressources

Node 24 et `npm --prefix web ci` sont nécessaires. Un checkout suffit à
`npm --prefix web run verify:map` et au build : aucune donnée distante n'est
téléchargée en CI. Pour refaire les transformations, télécharger l'original
Natural Earth épinglé dans le cache ignoré, depuis la racine (PowerShell) :

```powershell
New-Item -ItemType Directory -Force .tools/mr008
$mapSource = Get-Content data/map-sources/manifest.json -Raw | ConvertFrom-Json
Invoke-WebRequest -Uri $mapSource.sources[1].source_url -OutFile .tools/mr008/natural-earth-land.geojson
npm --prefix web run prepare:map
npm --prefix web run verify:map
```

Sous Linux, créer le même dossier et télécharger l'URL du manifeste avec `curl
--fail --location --output`. Le script refuse des octets d'entrée différents
des SHA-256 enregistrés et ne fait aucun appel réseau. Une modification voulue
de source exige la revue des droits et métadonnées, puis la régénération du reçu.
Les formats de sortie sont déterministes ; aucune date d'exécution n'est injectée.

## Validation observée

- `npm --prefix web run lint`, `typecheck`, `format:check` et `build` : réussis.
  Le build vérifie le reçu frontend autonome ; les tests vérifient aussi le reçu
  complet et l'original IGN. Vite signale le module
  MapLibre supérieur à 500 ko : avertissement conservé, import dynamique séparé.
- `npm --prefix web test` : 8 tests React, 2 tests Worker et 2 tests de packaging
  autonome réussis, avec vérification complète des sources et sorties.
- `uv run --locked pytest -m "not integration"` : 32 réussis, 3 tests PostGIS
  désélectionnés ; Ruff, format Python et mypy réussis.
- `npm --prefix web run test:e2e` : 10 réussis, Chromium réel, bureau et Pixel 7.
  Sélection par géométrie et clavier, zoom/recentrage, attributions, sources
  absentes puis relance, WebGL absent, API inaccessible et débordement horizontal.
  Premier essai : 8 délais d'attente sur 10 avec 8 contextes logiciels simultanés.
  La limite de 2 workers donne 10 réussites en 11,6 s, puis 11,2 s sur la version
  finale, sans retries automatiques.
- `npm --prefix web audit --omit=dev` : zéro vulnérabilité signalée, après
  activation du magasin de certificats système (`NODE_USE_SYSTEM_CA=1`). Le
  premier appel sans ce réglage a échoué sur la chaîne de certificats ; aucun
  contrôle TLS n'a été désactivé.
- Captures finales [bureau](assets/MR-008-desktop.png) et
  [mobile](assets/MR-008-mobile.png) relues visuellement : géométries présentes,
  sélection visible, texte et crédits lisibles, aucune superposition des contrôles.
- [PR #14](https://github.com/canaps13/MycoRadar/pull/14), code `52452b9` :
  [Bootstrap Linux et Windows](https://github.com/canaps13/MycoRadar/actions/runs/40973030156),
  [Compose/PostGIS et navigateur](https://github.com/canaps13/MycoRadar/actions/runs/40973030168)

  réussis. Les conclusions et étapes GitHub réellement observées sont conservées

  Le commit de preuve documentaire déclenche une nouvelle exécution ; les liens

La [première CI Compose](https://github.com/canaps13/MycoRadar/actions/runs/40972608925)
a échoué sur le contrôle d'intégrité, avant les tests
PostGIS : le contexte Docker existant ne contient que `web`, sans manifeste à la
racine du dépôt. Le build vérifie désormais un reçu frontend autonome, avec un
test d'exécution dans un dossier temporaire isolé et un test de refus de géométrie
altérée. Le contrôle du manifeste et de l'original IGN reste dans les tests CI.
Les géométries, le rendu et la configuration Docker n'ont pas changé.

Compose/PostGIS non lancés localement pour cette unité frontend sans migration ;
leur validation réelle est confiée au workflow existant `Local environment`.
Aucun déploiement ni modification de l'API publique n'est effectué par cette PR.

## Retour arrière

Revenir sur le commit MR-008 et reconstruire le frontend. Pas de migration,
secret, service tiers, abonnement ou changement de données privées. Les sources
cartographiques ne sont pas des données scientifiques validées pour un modèle.

géographiques appartiennent à MR-009.
