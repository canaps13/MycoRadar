# MR-007 — Grille multirésolution et masques explicites

29 octobre 2026. Base synchronisée `a969909`, branche
`feat/MR-007-geographic-grid`. La PR MR-006 #11 était livrée et verte mais ouverte ;
le job est donc indépendant de la persistance SQL. Pas de reprise de son code
dans cette PR. Dépôt initial propre, remote et fetch contrôlés.

## Livrables

- Moteur générique EPSG:6933, identifiants stables, cellules canoniques, relations
  territoire/cellule, intersections et surfaces projetées ; limites explicites
  aux pôles et à l'antiméridien.
- Manifeste typé, CRS/droits/provenance/empreinte et budgets vérifiés ; masques
  terrestres/forestiers avec couverture explicite et états incomplets honnêtes.
- Job backend hors HTTP, artefact avec inputs et versions, publication atomique
  sans écrasement et rejeu idempotent. Aucun score ou endpoint ajouté.
- Configuration pilote et trois contours administratifs IGN réels, sous LO 2.0,
  gelés dans Git. Aucun masque forestier réel inventé en attendant MR-012.
- Groupe `geo` dédié ; inclus dans dev pour la CI, exclu de l'image HTTP standard.
  [Contrat et usage](grid-job.md).

## Validation observée

Tests locaux : **41 nouveaux tests de grille/job réussis**. La suite complète
finale donne **73 passed, 3 skipped** ; les skips sont les vrais tests PostGIS,
non activés sur une base applicative.
Ruff lint/format et mypy passent. Audit `uv --system-certs audit --locked` :
aucune vulnérabilité connue ni statut adverse parmi **43 packages**, commande
expérimentale. Aucune nouvelle dépendance npm.

Premier passage ciblé : **33 passed, 4 failed**, car GEOS ne considère pas
`covers(EMPTY)` comme vrai. Le masque positif vide, lorsqu'une couverture valide
est explicitement fournie, est maintenant traité comme un zéro connu ; les
tests de forêt vide, mer connue et couverture partielle passent. Le passage à
l'API Shapely moderne a aussi retiré l'avertissement de dépréciation observé.

Le job complet 1/2 km a été exécuté puis rejoué sur l'extrait réel. Il produit
**19 952 associations cellule/territoire pour 19 551 cell_id distincts**, avec
**34 865 candidats**, sous le budget de 50 000. Les associations frontalières
expliquent la différence ; pas de duplication de l'identité physique d'une cellule.
Les masques absents produisent `unavailable`, pas des fractions zéro.
Le résultat volumineux reste dans `.tools`, hors Git ; son
[reçu d'exécution](evidence/MR-007-job.json) conserve empreintes, runtime et
comptages. Le dernier passage complet a pris 30,7 s sur cet hôte, observation
locale et non engagement de performance. La relance a renvoyé `created=False`.
L'export des dépendances `--no-dev` a confirmé l'absence de Shapely/pyproj/NumPy
dans les dépendances HTTP de production.

Le test CI sur les contours réels utilise un pas plus grossier pour un smoke
borné, sans accès réseau. Les tests de forêt/mer/absences sont synthétiques.
Tests navigateur et PostGIS non relancés localement pour ce job sans changement
d'API/web ; les workflows existants les exécutent sur la PR. CI en attente,
statut `IN_PROGRESS` jusqu'aux preuves observées.

## Limites et retour arrière

Pas de grille mondiale calculée, pas de masque réel de forêt/terre admis, pas de
gain scientifique validé et pas de précision locale inférée. Le seuil de calcul,
la densification et le pas projeté ne sont pas une résolution effective source.
Les polygones non coupés à l'antiméridien et les territoires hors ±86° échouent
explicitement. L'admission des données sensibles MR-048 reste nécessaire avant
toute ingestion concernée ; cette commande n'accepte que des polygones publics.

Pas de migration ni de données applicatives modifiées. Revert de cette PR puis
`uv sync --locked` pour revenir aux dépendances antérieures ; les sorties restent
des fichiers isolés. Pas de déploiement, provisioning cloud ni autre dépôt modifié.
