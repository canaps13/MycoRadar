# MR-044 — Explorateur connecté à la publication API

La tranche technique relie MapLibre aux vrais contours IGN de MR-009 et à
leurs métadonnées. La branche `feat/MR-044-connected-explorer` part de `main`
propre et synchronisé `3e15ac8`. Aucune migration, ingestion de nouvelle source,
publication Cloudflare ou fusion de PR n'est effectuée par cette unité.

**MR-044 reste IN_PROGRESS** : aucun taxon réel n'est encore admis dans le
catalogue. Le choix du premier pilote dépend de MR-010/MR-045, conformément à
[MVP_DELIVERY](MVP_DELIVERY.md). Le sélecteur est visible et désactivé ; une
fixture explicitement inventée vérifie son fonctionnement avec une espèce,
sans constituer une admission scientifique ni une preuve de présence réelle.

## Contrat et rendu

`GET /v1/exploration` fournit une vue bornée de la publication pilote, documentée
dans OpenAPI. Paramètres optionnels :

| Paramètre | Contrat |
|---|---|
| `region_id` | Identifiant d'un secteur configuré du pilote ; absence = vue d'ensemble |
| `taxon_id` | Taxon explicitement admis dans le contexte et lié au territoire ; aucun par défaut |
| `valid_at` | Date calendaire ISO stricte `YYYY-MM-DD`, entre 1900 et 2100 ; défaut = jour courant dans le fuseau du territoire |
| `catalog_version` | SHA-256 attendu ; divergence = 409, relecture unique sans version côté client |

La réponse `partial` contient versions catalogue/contexte, géométries, emprises,
points d'étiquetage déjà préparés, sources et sélection effectivement appliquée.
Habitat et fructification ont chacun `status:unavailable`, `score:null`,
`computed_at:null`, `effective_resolution_m:null`. Une date future ne crée pas
de prévision. Les paramètres inconnus ou répétés sont refusés ; les erreurs
typées ne reflètent pas l'entrée utilisateur.

Les trois secteurs restent des limites administratives, sans masque forestier
ni observation. Le contexte Provence est une configuration, pas une règle dans
le contrat de service. Le fond Natural Earth reste l'extrait local attribué de
MR-008 ; une publication dépassant sa couverture laisse la carte indisponible
et conserve la liste utilisable. L'API ne revendique aucune couverture mondiale.

Le client attend la publication initiale avant d'initialiser WebGL, filtre à
l'interaction et abandonne les requêtes dépassées ou expirées après cinq secondes.
Il valide le contrat reçu et refuse un score ou une sélection incohérente. À
chaque chargement, les résultats courants sont effacés. En cas d'échec, seuls
les derniers contours reçus sont conservés ; sans publication reçue, le fond
local daté est utilisé. Un bouton permet de recharger les données. Les données
de requête ne sont ni persistées dans le navigateur ni ajoutées à l'URL de page.

La fiche de qualité distingue collecte de l'extrait et acquisition des données.
La collecte IGN reste `2026-10-29T17:06:20Z`, issue du lot déjà admis de MR-009.
Date d'édition, âge réel et résolution effective restent inconnus ; aucune
fraîcheur n'est déduite de la date sélectionnée ou de la santé HTTP.

## Préparation et Dockerfile API

`data/catalog/manifest.json` décrit aussi `explorer` : secteurs, cadrage,
fuseau, points d'étiquetage, référence/empreinte IGN et liste vide de taxons.
Les points et emprises reprennent la préparation d'affichage MR-008 ; aucun
calcul géospatial lourd n'a lieu dans le navigateur ou pendant une requête.

```powershell
$env:PYTHONPATH='api/src'
uv run --locked python scripts/prepare_catalog.py --check
uv run --locked python -m mycoradar.exploration --check-bundle
```

Le préparateur hors réseau produit `public-catalog.json` et
`explorer-context.json`, chacun avec SHA-256, dans `api/src/mycoradar/data`.
Les octets du catalogue IGN existant restent identiques. Les références du
contexte sont vérifiées contre le catalogue au démarrage ; publication absente
ou incohérente = 503 sans casser `/health`. Les requêtes ne lisent pas le disque.

`infra/api.Dockerfile` exécute `--check-bundle` après la copie du package et
avant le passage à l'utilisateur non privilégié. Le paquet fonctionne sans
`web/`, sans le dossier racine `data/`, sans base et sans modules géospatiaux.
La commande Uvicorn désactive les journaux d'accès par défaut afin de ne pas
y consigner les paramètres de sélection ; les messages de démarrage restent
disponibles. Cette option ne configure pas un futur proxy de production.
Le smoke Compose vérifie la route réelle dans l'image API et via le proxy web.

## Validation

Validation locale observée : 148 tests Python réussis, dont 19 tests exploration ;
51 tests PostGIS désélectionnés. Ruff lint/format et mypy réussis. 22 tests React
et quatre tests Node (Worker/paquet cartographique), ESLint, TypeScript et build
réussis. L'avertissement Vite concernant le chunk MapLibre supérieur à 500 ko
persiste ; il est chargé séparément à l'ouverture de la carte.

Les tests API contrôlent le vrai lot IGN, les erreurs, le calendrier Paris à
la frontière de jour, la reproductibilité, l'absence d'accès disque en requête,
et le paquet isolé. Les tests client contrôlent sélection, date, conflits de
version, réponses tardives, délai dépassé, état vide, reprise et refus de
réponses incompatibles. Taxon et géométrie simplifiée des tests unitaires sont
explicitement synthétiques ; ils ne sont jamais embarqués comme publications.

Les 16 tests navigateur réussissent sur bureau et mobile, contre FastAPI et le
build web via le proxy réel : sélection de polygone, date, provenance, zoom et
recentrage pendant un zoom, panne/reprise API, source cartographique absente et
absence de WebGL. Les [captures bureau](assets/MR-044-desktop.png) et
[mobile](assets/MR-044-mobile.png) ont été ouvertes et vérifiées visuellement.

Les premiers essais ont échoué : recentrage ignoré pendant le chargement après
zoom, recréation inutile du fond local pendant une revalidation hors connexion,
et réponses JSON tronquées via le proxy local Windows. Les deux premiers cas
sont corrigés dans le cycle de vie de la carte. Le proxy Vite utilise maintenant
un agent HTTP avec maintien de connexion ; le contrôle diagnostic suivant a
reçu 50 réponses complètes via le proxy, puis la suite navigateur a réussi sans
retry. Les tentatives intermédiaires de changement d'en-tête seul et du chemin
`fetch` n'avaient pas corrigé la troncature et ne sont pas retenues.

Le code `738c497` de la [PR #17](https://github.com/canaps13/MycoRadar/pull/17)
est validé par [Bootstrap Linux/Windows](https://github.com/canaps13/MycoRadar/actions/runs/41092742369),
[Compose/PostGIS](https://github.com/canaps13/MycoRadar/actions/runs/41092741434)
et [conventions](https://github.com/canaps13/MycoRadar/actions/runs/41092984770).
Compose a exécuté le contrôle du paquet pendant le build Docker, le smoke de
l'explorateur API/proxy, 51 tests PostGIS, le rejeu des migrations et 16 tests
navigateur. Le [reçu CI](evidence/MR-044-ci.json) conserve les conclusions et
étapes réellement observées. Le premier contrôle de conventions a échoué à
cause d'un BOM UTF-8 au début du corps de PR ; sa suppression a permis le
contrôle suivant sur le même code, sans changer le validateur.
Le commit documentaire déclenche une nouvelle CI à vérifier sur le SHA courant.
Compose/PostGIS ne sont pas exécutés localement pour cette unité sans migration ;
leur validation est confiée au workflow CI existant qui construit les images.
La preview publique garde `/api/*` en 503 tant que FastAPI n'est pas hébergé.

Retour arrière : revert de MR-044, reconstruction API/web. Aucun changement de
schéma, de secret ou de donnée privée ; pas de dépense cloud.

## Vérification déterministe du recentrage — 31 octobre 2026

La branche a été synchronisée avec `main` `36e4ee8` par le commit de branche
`d9d6f0a`. Cela reprend les contrôles de confidentialité MR-048 déjà intégrés
à `main` ; aucune PR n'est fusionnée dans `main` par cette opération.

Le composant MR-044 contient déjà le recentrage par `stop().fitBounds(...)`,
sans condition `isStyleLoaded()`. Les deux nouveaux cas de `MapView.test.tsx`
vérifient la frontière caméra avec un moteur simulé : après un zoom en cours,
la demande de vue d'ensemble restaure l'emprise configurée et annule l'animation,
que le style soit chargé ou non, sans recréer le moteur ou inventer une sélection.
Le faux moteur modélise la caméra ; il ne remplace pas les tests WebGL réels.

La [preuve de régression](evidence/MR-044-recenter-regression.json) conserve une
vérification négative réellement exécutée : restaurer temporairement **le seul
garde-fou** `isStyleLoaded()`, en conservant `stop()`, fait échouer le cas style
en chargement tandis que le cas style chargé réussit. Après restauration des
octets originaux, les deux cas passent. Le SHA-256 du composant est identique
avant/après ; cette unité ne change pas son code de production.

Cela démontre le mécanisme d'un recentrage ignoré pendant un chargement,
compatible avec le symptôme observé lors du test mobile de MR-013. Ce n'est
pas une reconstruction de la trace caméra de cet ancien run : sa cause unique
n'est pas établie. Aucun délai, tolérance, retry ou test navigateur n'a été
assoupli pour obtenir ces résultats.

Résultats locaux sur la branche synchronisée :

  Ruff lint/format, mypy (20 sources), vérifications catalogue et paquet API réussis.
