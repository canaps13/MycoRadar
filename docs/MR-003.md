## Base et périmètre

29 octobre 2026. La [PR #2](https://github.com/canaps13/MycoRadar/pull/2) a été
fusionnée après vérification des contrôles verts, dans la continuité de
l'autorisation de commit/fusion et de poursuite autonome donnée dans la session.

Branche : `feat/MR-003-local-environment`, créée depuis `main` propre.

La tâche ajoute l'environnement local, sans créer le schéma métier MR-006 :

- Compose : PostGIS, migration ponctuelle, API et web ; ports de boucle locale
  55432, 18000 et 15173 pour préserver les processus déjà présents sur 8000/5173.
- `.env.example` public de développement, secrets réels exclus de Git ; réglages
  `PG*` uniquement côté serveur, URL de connexion construite par SQLAlchemy.
- Python/Node/uv/PostGIS épinglés par digest dans les images ; dépendances
  verrouillées. API et web s'exécutent avec des utilisateurs non root.
- Migration `0001_postgis` idempotente : activation de PostGIS si nécessaire,
  suivi Alembic. Le downgrade conserve l'extension et ses données ; il retire
  uniquement la révision. Aucun `DROP EXTENSION`, aucune table métier anticipée.
- `/health` vérifie la vie HTTP. `/ready` vérifie PostGIS et la révision Alembic,
  renvoie 503 en cas d'indisponibilité, sans exposer l'erreur de connexion.
- Le web sert un build via l'aperçu local Vite, avec proxy interne vers l'API.
  Aucun score, source, licence fournisseur, résolution ou fraîcheur inventé.
- CI `Local environment` : construction Compose standard, vérifications HTTP,
  vrais tests PostGIS, rejeu de migration et navigateur sur le web conteneurisé.
  Cela ne termine pas MR-004, qui reste la tâche dédiée à la CI complète.

## Échecs rencontrés et limites vérifiées

1. Premier build API : `UnknownIssuer` vers les wheels Python. La chaîne TLS
   présentée par le réseau local a été validée avec le magasin Windows. Les CA
   publiques correspondantes sont restées dans `.tools/build-ca.pem`, ignoré de
   Git. La surcharge `infra/compose.build-ca.yaml` les monte en secret BuildKit
   durant uv/npm uniquement. TLS n'a pas été désactivé ; aucun certificat n'est
   copié dans une couche de l'image. Le build a ensuite réussi. La CI utilise
   la commande standard sans cette surcharge ni le certificat de la machine.
2. Lint initial : imports non triés et typage des résultats SQLAlchemy incomplet.
   Corrections appliquées ; lint, format et mypy ont ensuite réussi.
3. Tests navigateur concurrents sous Windows : timeouts de chargement de modules
   avec le serveur Vite de développement à froid. Les mêmes tests ont passé en
   séquence puis en parallèle après le premier chargement. Le conteneur sert
   désormais un build produit à la construction, plutôt que compiler à la requête.
   Un lancement concurrent immédiatement après reconstruction a encore donné
   deux timeouts ; les quatre tests sont ensuite passés en séquence après un
   redémarrage web, sans modifier les assertions ni augmenter les délais.
   La cause exacte des ralentissements concurrents sur cet hôte n'est donc pas
   revendiquée comme résolue. Les quatre tests ont réussi en concurrence normale
   sur la pile Compose en CI Linux.
4. Audit npm initial sans magasin Windows : échec TLS. Relance avec
   `NODE_USE_SYSTEM_CA=1` réussie, sans modification de la configuration globale.

## Retour arrière et suite

`docker compose stop` arrête uniquement cette pile et conserve ses données.
Ne pas supprimer le volume ni nettoyer Docker globalement. La migration initiale
ne retire jamais PostGIS ; les migrations métier futures auront leurs propres
procédures. Une PR de revert peut retirer le code si nécessaire sans effacer
les données locales. Aucun déploiement, ressource cloud payante ou modification
de Synergia effectué. Prochaine tâche : MR-004.
