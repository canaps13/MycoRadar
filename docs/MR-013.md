# MR-013 — Lecture raster hors ligne et échantillon SoilGrids

**Statut : IN_PROGRESS.** Cette tranche fournit un lecteur GeoTIFF borné et
un échantillon de sol réel rejouable. Le relief réel n'est pas intégré et la
géologie BRGM reste bloquée par R1. Les fixtures de terrain et de catégories
testent des conventions techniques, pas la disponibilité de ces produits.
Aucun score, couche publique, jointure écologique ou changement de schéma SQL.

## Métadonnées scientifiques conservées

Il s'agit d'une **prédiction de pH du sol**, statistique moyenne pour la
profondeur 0–5 cm, et non d'une analyse de sol locale. Aucune incertitude
quantile n'est calculée. Le [catalogue ISRIC](https://maps.isric.org/soilgrids.html)
donne pH × 10 : l'entier est multiplié une seule fois par 0,1. Le fichier ne
déclare pas d'unité ; son scale/offset est 1/0. La description WCS conservée
[en XML](evidence/MR-013-soil-describe.xml) annonce l'unité générique incohérente
`W.m-2.Sr-1` : elle n'est pas interprétée comme unité de sol.

Le CRS interne Goode Homolosine interrompu WGS84 est conservé intégralement,
sans autorité EPSG inventée. L'identifiant de service WCS `152160` n'est pas
réassigné au fichier. Le pas observé est 250 m en coordonnées projetées, conforme
au pas nominal annoncé du produit ; il ne prouve aucune résolution effective.
Pas de reprojection ou rééchantillonnage demandé, ni réalisé par le lecteur.

Date de publication exacte du raster, millésime, `data_cutoff` et résolution
effective restent `null`. L'année 2021 de l'article ne date pas ce lot ; l'heure
de capture ne mesure pas la fraîcheur des données. Une future jointure datée
MR-014 devra refuser d'inventer leur antériorité ou leur pertinence locale.

## Zeros ambigus

Le GeoTIFF n'a **aucun NoData déclaré**, son masque GDAL marque tout valide et
la description WCS a `nilValues` vide. Huit cellules contiennent pourtant zéro.
Leur signification n'est pas établie : ne pas les qualifier d'océan, de zone
urbaine ou de NoData confirmé, ni les intégrer comme pH connu.

Le manifeste versionne une exclusion opérateur des valeurs brutes zéro avec
sa raison et sa politique. Résultat : 64 cellules, 56 valeurs normalisées,
huit `null` par prudence, zéro NoData déclaré. `coverage_status=partial` décrit
uniquement cette fenêtre technique, pas une couverture scientifique admise.
Les 56 valeurs sont entre 7,3 et 7,6 ; la moyenne arithmétique de fenêtre n'est
ni une mesure ni une estimation validée d'un secteur. Les décimales du calcul
ne donnent aucune précision physique supplémentaire.

Cette règle est propre au lot. Une altitude zéro reste valide lorsqu'aucune
convention explicite ne l'exclut ; le test de terrain synthétique le vérifie.

## Contrat du lecteur

`mycoradar.raster_job` charge un manifeste strict : chemin contenu dans son
répertoire, empreinte, bande, CRS concordant, fenêtre entière, provenance,
nature, profondeur/statistique du sol, conversion explicite ou embarquée et
plage/exclusions optionnelles. Aucun CRS ni millésime par défaut. Les fichiers
restent locaux et autonomes : pilote GTiff seulement, lecture mémoire, aucun
VRT, sous-dataset, sidecar PAM/masque externe, GCP/RPC ou affine tourné accepté.
Une livraison nécessitant ces éléments doit être préparée séparément et revue.

Bornes avant lecture : manifeste 100 000 octets, raster 64 Mio, fenêtre
100 000 pixels, dataset 25 millions de pixels / un million par dimension,
bloc décompressé un million de pixels. Entiers jusqu'à 32 bits et flottants
réels ; entiers 64 bits et complexes refusés. GDAL : un thread, cache 16 Mio.
Ces bornes ciblent les petits extraits techniques, pas une ingestion nationale.

Masque invalide, NoData déclaré, non-finis bruts ou après conversion, valeurs
hors plage et exclusion opérateur donnent `null`, avec compteurs distincts
qui peuvent se recouper. Le total invalide compte chaque cellule une fois.
NoData explicite prime même si un masque interne dit valide. Aucune interpolation.
Unités embarquées incompatibles et conversions contradictoires sont refusées ;
une conversion identique embarquée/explicite est appliquée une seule fois.
Une catégorie reste entière, sans conversion ni moyenne ; sa signification
nécessitera un codebook admis, non fourni ici pour la géologie.

L'artefact inclut SHA d'implémentation et versions Python/Rasterio/GDAL/NumPy/PROJ,
OS et architecture. Le rejeu identique sur le même moteur conserve le fichier ;
un résultat différent refuse l'écrasement. Changer de plateforme peut changer
l'identifiant : la capture Windows n'est pas une promesse d'identité binaire
avec Linux. Le [résultat gelé](../data/rasters/soilgrids-sample/normalized.json)
et son [reçu](evidence/MR-013-sample.json) documentent cette exécution précise.
La CLI renvoie un diagnostic JSON fixe en échec, sans contenu ou chemin privé.

## Docker et recette

Voir les [commandes du README](../README.md#lire-un-raster-hors-ligne-mr-013).
La cible explicite `raster-job` utilise le groupe `geo` et `libexpat1` ; le
build par défaut conserve Uvicorn, UID 10001 et aucune installation Rasterio.
Le conteneur de job s'exécute sans réseau avec l'entrée montée en lecture seule.
L'API et le Worker HTTP n'exécutent aucun calcul raster.

Réussites locales observées :

- `uv run --locked pytest` : 372 réussis, 51 PostGIS ignorés faute de base de test activée.
- `uv run --locked pytest api/tests/test_raster_job.py` : 29 réussis.
- Ruff lint/format, mypy (20 sources) et `git diff --check` : réussis.
- Deux relectures de l'extrait : même identifiant, `created=true` puis `false`.
- Builds API par défaut et cible raster réussis ; API UID 10001, contrat santé
  présent, Rasterio absent. Après correction, smoke raster sans réseau réussi :
  56 valeurs, huit exclusions, Rasterio 1.5.2 / GDAL 3.12.2, UID 10001.

Échec observé et corrigé : premier smoke du conteneur raster incapable de
charger `libexpat.so.1` malgré un build réussi. La cible de job installe désormais
`libexpat1` et le smoke sans réseau a réussi après reconstruction. Une ligne XML
de test trop longue a également été corrigée après le premier passage Ruff.
La [PR #22](https://github.com/canaps13/MycoRadar/pull/22) a quatre contrôles verts
sur le commit d'implémentation `834868c` : Bootstrap Linux/Windows,
Compose/PostGIS et conventions. Le [reçu CI](evidence/MR-013-ci.json) conserve
SHA, URL, étapes et lignes de résultats effectivement observées :

- Bootstrap Linux et Windows : 372 tests Python réussis, 51 intégrations
  désélectionnées ; lint, format, mypy, huit React et build web réussis ;
  12 tests navigateur réussis sur chaque OS.
- Compose : build et pile saine, cible raster construite, smoke sans réseau
  à 56 valeurs/huit exclusions et absence de Rasterio dans l'API ;
  51 tests PostGIS réussis, 372 unités désélectionnées, rejeu des migrations
  et 12 tests navigateur réussis.

Les 51 tests PostGIS ignorés localement ont donc été exécutés en CI ; ce ne
sont pas 51 réussites locales. Le reçu vise le SHA de code ci-dessus ; une
mise à jour ultérieure des seules preuves doit aussi passer ses propres checks.
