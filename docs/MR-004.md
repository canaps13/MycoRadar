## Contrôles livrés

- Conservation des workflows Bootstrap Linux/Windows, Compose/PostGIS et
  conventions de PR, avec actions existantes épinglées par SHA et droits de lecture.
- ESLint : règles recommandées JavaScript/TypeScript et règles React Hooks,
  avertissements bloquants, sources/tests/configurations inclus, sorties ignorées.
- Commande `typecheck` indépendante ; le build conserve aussi son contrôle de types.
- Tests Python unitaires séparés des trois tests PostGIS du job Compose.
- Résumé Actions exécuté avec `always()`, fondé sur `steps.*.outcome`.
  Les résultats manquants/inconnus, skipped et cancelled ne deviennent jamais
  des succès. Un test vérifie aussi le cas d'un échec toléré dont la conclusion
  serait success. Aucun contrôle n'utilise `continue-on-error`.

## Compatibilité des dépendances

L'installation initiale du linter a été refusée par npm (ERESOLVE) :
typescript-eslint 8.72.1 accepte TypeScript `>=4.8.4 <6.1.0`, alors que le dépôt
utilisait 7.0.2. Le compilateur de développement est ramené à `~6.0.3`, sans
forcer la résolution ni ignorer les peer dependencies. Installation propre,
lint, typage, tests et build vérifiés avec le lockfile mis à jour.

## Risques et retour arrière

Le changement de version majeure de TypeScript peut affecter les futures
extensions du projet ; les sources actuelles compilent. Les workflows s'arrêtent
au premier échec, les contrôles suivants sont explicitement non exécutés dans
le résumé. Si le runner s'arrête brutalement, le résumé peut manquer : consulter
alors le statut et les logs du job. Aucun mécanisme ne garantit un résumé après
perte du runner.

affectée, aucune ressource cloud créée, aucun déploiement production.
