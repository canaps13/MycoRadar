Ne pas réutiliser ces tests de downgrade sur une base applicative, même si son
nom a été modifié pour satisfaire artificiellement la garde.

Premier passage : **48 tests PostGIS réussis, 3 échoués**, car les typmods
`geometry(...,4326)` acceptaient le SRID 0 et le remplaçaient par 4326.
Le stockage utilise maintenant `geometry` avec contraintes séparées SRID/type/2D.
La revue de `geometry_columns` confirme que les outils retrouvent le type, le
SRID 4326 et la dimension 2. Aucun CRS initial n'est inventé à l'insertion.

Après correction et recréation du schéma dans la base isolée : **83 tests Python
réussis**, dont **51 tests PostGIS**, aucun skip. Ruff lint/format et mypy
réussis. Le test ciblé de retour `0002` → `0001` → `head`, extension et table
témoin conservées, a aussi réussi avant la suite complète.

La génération `alembic upgrade head --sql` et les liens internes ont été vérifiés.
Le build Compose avec la surcharge CA locale existante a réussi, sans désactiver
TLS. `scripts/check_local_stack.py` visant les ports dédiés a vérifié HTTP,
readiness, page et proxy. Une requête SQL a confirmé la base isolée, la révision
`0002_geospatial_foundation`, PostGIS 3.6 et zéro occurrence. Un premier essai de
cette requête ad hoc manquait de `PYTHONPATH=api/src` ; la relance correctement
configurée a réussi. Les conteneurs ont ensuite été arrêtés sans supprimer le volume.

Une première CI entièrement verte sur `663924b` a exécuté les 51 tests PostGIS,
les 32 autres tests Python, les contrôles statiques, 6 tests React et 4 tests
navigateur par système ainsi que sur la pile Compose. Après alignement des noms
sur MR-043, la suite locale complète a de nouveau passé **83 tests**, dont les
**51 PostGIS**, sans skip ; Ruff, formatage, mypy et SQL hors ligne ont réussi.

## Limites et retour arrière

Le schéma n'exécute pas d'ingestion, de réconciliation taxonomique, de génération
de grille ni de score. Les fixtures sont fictives. Validation légale, intersection
cellule/région, précision et masquage effectifs, RLS et autorisations applicatives
restent à implémenter dans les tâches concernées. Aucune présence réelle ou
fraîcheur scientifique n'est revendiquée.

Le downgrade supprime les 11 tables métier et leurs données, sans CASCADE et sans
retirer PostGIS. Il n'est testé que sur une base isolée ; exécution réelle soumise
à l'approbation spécifique d'AGENTS.md. Pas de migration destructive applicative,
de déploiement ni de frais cloud pendant ce travail. Revert du code et conservation
du schéma à privilégier après mise en service, avec coordination de `/ready` et
de la révision attendue. Voir le contrat pour la procédure et ses limites.
